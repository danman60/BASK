# M1 — Web demo build (the five loops)
## Execution plan. Parents: IMPLEMENTATION_SPEC.md (M1 scope, §0 demo mandate), DESIGN_SPEC.md (visual acceptance bar), PITCH.md (the beats these screens must serve).

**Goal:** the product Nick sees. Every surface in the pitch script, real and interactive, on the M0 spine.

**Visual acceptance bar:** `mockups/*.html` + their PNGs. A screen is not done until a screenshot of it sits beside the mockup without embarrassment — same warmth, hierarchy, restraint. Tokens/components already exist (`@bask/tokens`, `@bask/ui`); do not re-derive them.

**Executor notes:** deviations → `## Deviations` in this file. Steps are intent + constraints; component internals are your judgment. Screenshot every iteration and DM it (`~/tg-dm.sh --file <png> "<context>"`). Assign your lane's dev port (below) — every M0 lane defaulted to 3417 and collided.

## Standing constraints (from M0, do not rediscover)
- Prisma 7 needs `@prisma/adapter-pg`. Migrate MUST use `DIRECT_DATABASE_URL` (:5432) — :6543 pgbouncer hangs silently forever. New migrations: `pnpm db:migration:new` → `pnpm db:check` → `pnpm db:deploy`. Never `prisma migrate dev`.
- Always import the shared client (`import { db } from '@bask/db'`) — never `process.env.DATABASE_URL` in a route. Route-module clients must be lazy.
- ThemeProvider lives in the ROOT layout. Don't add another.
- `packages/core/consent` is the ONE filter every Compass surface reads through. No Compass query may bypass it.
- Insight `evidence` uses the single `Evidence` zod schema from `@bask/core`. UI props read that shape — do not invent a second.
- No auth machinery (explicit non-goal until M3). Roles come from the URL/presenter panel.
- Nothing auto-sends. Guardrail validators run on every generation.
- `pnpm demo:reset` (~32s) then `demo:advance --days N` regenerates state; keep every screen working from a fresh reset.

## Merge protocol (learned from M0)
Lanes own disjoint routes/components. Shared files (root layout, nav, `packages/ui` primitives) belong to Lane 1 — other lanes request additions rather than editing. Merge order 1 → 2 → 3 → 4 → 5 → 6, running `pnpm build && pnpm typecheck && pnpm test && pnpm lint` after each. Re-verify every merged surface in a real browser: M0 proved that three separate bugs were invisible inside their own lanes and only appeared once merged.

## Exit gate
`pnpm demo:verify` green on the full PITCH.md path · every mockup-backed screen screenshotted beside its mockup and DM'd · a non-technical tester completes check-in + campaign creation unaided · all five loops runnable from a fresh `demo:reset` · consent tier flip demonstrably changes Compass · build/typecheck/lint/test green.

- 2026-08-07 · Lane 4 · **Server actions instead of tRPC procedures for Lane 4 writes.** `packages/api/src/routers/domains.ts` is a single file all six lanes would have to edit in the same week. Every Lane 4 write is a form submit on a page Lane 4 owns, so they live in `app/inventory/actions.ts` and `app/insights/actions.ts`. Nothing bypasses the shared client — `db` is always the one from `@bask/db`. The `inventory`/`insights` tRPC namespaces are left as the M0 stubs for whoever needs them on mobile in M2.
- 2026-08-07 · Lane 4 · **Lane 4 components live in `apps/web/src/components/lane4/`, not `@bask/ui`.** The merge protocol gives Lane 1 `packages/ui` for M1. `GapSlider`, `StatRow`, `Chip`, `Sparkline` and `EvidenceSentence` are DESIGN_SPEC §4 vocabulary and are named to match, so promoting them into `@bask/ui` after the merge is a move rather than a rewrite.
- 2026-08-07 · Lane 4 · **Additive entries appended to `packages/ui/src/guidance/guidance.ts`** (4 metrics, 6 tips, 6 whispers, 3 empty states, each under a `Lane 4` comment banner). The dictionary keys are typed unions, so there is no way to key a popover without adding to that file. Appended at the end of each object to keep the merge conflict trivial.
- 2026-08-07 · Lane 4 · **Staff challenges are `ActivityEvent` rows, not a new table.** "Create staff challenge" needs a goal object the Floor can read. Adding a `StaffChallenge` model would mean a Prisma migration against the database all six lanes are sharing this week. The challenge is written as `action: 'staff_challenge_created'` with `{ metric, label, target, windowDays }` in the metadata — which is where the Floor would read it from anyway. Promote to a real table when Lane 2's Floor consumes it.
- 2026-08-07 · Lane 4 · **Peer benchmark contributions are derived, not measured.** PRODUCT_SPEC §20 seeds one operating salon plus eleven dealer accounts that have a health score, an order book and a region but no session rows. Peer values therefore come from documented monotone maps over `account.health_score` (`server/peers.ts`, `PEER_MAPS`), labelled on screen as derived. The subject salon's own side of every comparison is real, and the arithmetic that turns a gap into dollars runs entirely on its real traffic. Cohort membership and suppression are real throughout: `contributesToCohorts` decides who is in, `filterCohort` decides whether the aggregate may be shown.
- 2026-08-07 · Lane 4 · **Catalogue "images" are deterministic colour tiles, not photographs.** No product imagery exists in this dataset and generating fake bottle shots is precisely what DESIGN_SPEC's slop test rules out. `ProductSwatch` derives a hue from the product category and a lightness from the SKU.
- 2026-08-07 · Lane 4 · **Webcam/`BarcodeDetector` scanning not built** (already CUT in IMPLEMENTATION_SPEC §6.2). `/inventory` owns the receiving *destination* — a focused field the wedge scanner types into, plus manual entry. It deliberately installs no global keystroke listener; that is Lane 2's, and two listeners racing for one keystroke burst is a live-demo bug. Unknown codes are logged as `scan_unknown_code`; the "new product?" sheet is M2 with the camera flow.

### Lane 4 findings for the merge
- **`low_stock` fires but does not make the card cut on day `2026-08-11`.** Verified by running the detector directly: it produces *"Cabana Bronzer runs out in about 8 days"* at $203, and `runInsightSweep` keeps `maxInsights: 5` ranked by monthly value — low_stock ranks 7th behind attachment ($9,868), two overstocks ($1,768 / $1,344), spray anomaly ($810) and soft capacity ($502/mo). Not a Lane 4 defect and not a data problem; a ranking property of the M0 sweep at this clock position. `/inventory` surfaces the same finding independently (Cabana Bronzer, 13 on hand, 8.3 days, flagged *Running out*), so the reorder loop does not depend on the card existing.
- **Shared-database hazard.** All six lane worktrees point at the same `bask` schema, so `pnpm demo:reset` in one lane truncates the tables the others are reading. Two lanes resetting at once leaves partially-seeded state that looks like a bug. Reset once, coordinate, and re-verify after any lane resets.
- **Pre-existing hydration warning on every route:** `data-theme="sunset"` on `<html>` differs between server and client render. It comes from the M0 `ThemeScript` in the root layout (Lane 1's file), not from Lane 4 code.
